# live-bootstrap pass 5: gcc 10.5.0 (x86)

The fifth pass of Kairo's live-bootstrap (`specs/DECISIONS.md` §49): it
goes on from pass 4's whole root (`bootstrap/live-bootstrap-python/`,
through the python chain, guile, and autogen) to **gcc 10.5.0**, with C
and C++, and binutils 2.41 rebuilt with it, in upstream's CI pass 2 for
[live-bootstrap](https://github.com/fosslinux/live-bootstrap) at
`b1ceced7`. It runs under the bubblewrap engine, as the earlier passes
do, with no host tool taking part.

Each step packages what it installed and checks the package against
live-bootstrap's `SHA256SUMS.pkgs`. The 2 packages are this pass's 8
children (`specs/DECISIONS.md` §41 sub-decision 6, §51, §58): gcc
10.5.0, providing `tool:gcc`, `tool:g++`, and `lib:stdc++:static`,
which require binutils, musl's headers, the kernel headers, and
`one_of` static or shared musl, chosen by whatever builds with them, and
confer nothing; since this gcc builds its runtime libraries shared too,
each of them, split out by `../live-bootstrap/split-gcc.sh`, as a child
of its own: `lib:stdc++:shared`, `lib:gcc:shared`, `lib:gomp:shared`,
`lib:atomic:shared`, `lib:itm:shared`, and `lib:quadmath:shared`, each
conferring itself `>=10.5.0`, the ABI these libraries have kept from
release to release; and binutils 2.41, rebuilt, as `tool:binutils`.
Each child requires what its programs and libraries load, as
`package.sh` reports it (§56).

## How it's put together

| Guest path | What | How it's pinned |
|---|---|---|
| `/` | pass 4's whole root: `usr/` and `etc/`, every package so far in `repo/`, and `state/` | artifact, via `data:live-bootstrap:x86:autogen-5.18.16` |
| `/steps` | live-bootstrap's `steps/`, at the commit the earlier passes ran; `start.sh` copies this directory's `steps/manifest` over it | source object, by commit |
| `/external/distfiles` | gcc 10.5.0's and binutils 2.41's tarballs | file sources, by SHA-256 |

| File | What it is |
|---|---|
| `kairo.toml` | The pins and placements above; one target, `x86`, run by pass 4's bash with `../live-bootstrap/pass/start.sh`, from the step after `build autogen-5.18.16 pass1.sh`; its artifact (installed at `/`) is `/usr` and `/etc`, every package so far in `repo/`, the `state/` the next pass needs, and this pass's packages extracted as children. The parent provides the whole root as `data:live-bootstrap:x86:binutils-2.41_1`, naming the package because binutils 2.41 is built twice. The children are generated by `../live-bootstrap/children.py`. |
| `steps/manifest` | live-bootstrap's manifest, truncated after binutils 2.41's second build; its lines up to autogen are pass 4's. |
| `import.sh` | Archives live-bootstrap and the distfiles, and creates the wrapper with `../live-bootstrap/pass/start.sh`, `package.sh`, `../live-bootstrap/split-musl.sh`, and `split-gcc.sh`. |

## Running it

Import passes 1 to 4 (their READMEs). Then:

```sh
bootstrap/live-bootstrap-gcc-10.5.0/import.sh <your actor id>
kairo build object:<wrapper id> --target x86 --actor <your actor id>
```

The build plans the earlier passes' `x86` targets first if their
artifacts aren't held.

The ignored test `crates/kairo-cli/tests/bootstrap_live.rs` builds this
pass after the first four when `KAIRO_LIVE_BOOTSTRAP_PASSES` is 5, then
builds the hello consumer's dynamic target again, which now compiles
with gcc 10.5.0. Pass 6 (`bootstrap/live-bootstrap-gcc-15.2.0/`) goes
on from this pass's root.
