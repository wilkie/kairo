# live-bootstrap pass 4: python and guile (x86)

The fourth pass of Kairo's live-bootstrap (`specs/DECISIONS.md` §49): it
goes on from pass 3's whole root (`bootstrap/live-bootstrap-gcc-4.7.4/`,
to gcc 4.7.4) through the next stretch of upstream's CI pass 2 for
[live-bootstrap](https://github.com/fosslinux/live-bootstrap) at
`b1ceced7`: python 2.0.1 and 2.3.7, each built twice, gperf 3.3, gettext
0.26, perl's Text::CSV, texinfo 7.2, libffi 3.5.2, then python 2.5.6,
3.1.5 (twice), 3.3.7, 3.4.10, 3.8.16, and 3.11.1, upstream's uninstall
of every python but 2.5.6 and 3.11.1, then libunistring 1.4.1, the Boehm
GC 8.2.12, guile 3.0.11, which 2.23, grep 3.12, sed 4.8, and autogen
5.18.16, which gcc 10's build uses next. It runs under the bubblewrap
engine, as the earlier passes do, with no host tool taking part.

Each step packages what it installed and checks the package against
live-bootstrap's `SHA256SUMS.pkgs`. The 23 packages are this pass's
children (`specs/DECISIONS.md` §41 sub-decision 6): `tool:python` at
each python's version, the last build of each (python 3.11.1 the
highest); `tool:gperf`; `tool:gettext` and `lib:intl`;
`lib:perl:Text-CSV`; `tool:texinfo` and `tool:makeinfo`; `lib:ffi`;
`lib:unistring`; `lib:gc`; `tool:guile` and `lib:guile`; `tool:which`;
`tool:grep` 3.12; `tool:sed` 4.8; and `tool:autogen`.

## How it's put together

| Guest path | What | How it's pinned |
|---|---|---|
| `/` | pass 3's whole root: `usr/` and `etc/`, every package so far in `repo/`, and `state/` | artifact, via `data:live-bootstrap:x86:musl-1.2.5_2` |
| `/steps` | live-bootstrap's `steps/`, at the commit the earlier passes ran; `start.sh` copies this directory's `steps/manifest` over it | source object, by commit |
| `/external/distfiles` | the 137 distfiles this pass's steps unpack, most of them the Unicode data python's builds generate tables from | file sources, by SHA-256 |

| File | What it is |
|---|---|
| `kairo.toml` | The pins and placements above; one target, `x86`, run by pass 3's bash with `../live-bootstrap/pass/start.sh`, from the step after `build musl-1.2.5 pass3.sh`; its artifact (installed at `/`) is `/usr` and `/etc`, every package so far in `repo/`, the `state/` the next pass needs, and this pass's packages extracted as children. The parent provides the whole root as `data:live-bootstrap:x86:autogen-5.18.16`. The children are generated by `../live-bootstrap/children.py`. |
| `steps/manifest` | live-bootstrap's manifest, truncated after autogen; its lines up to musl 1.2.5's third build are pass 3's. |
| `import.sh` | Archives live-bootstrap and the distfiles, and creates the wrapper with `../live-bootstrap/pass/start.sh`, `package.sh`, `../live-bootstrap/split-musl.sh`, and `split-gcc.sh`. |

## Running it

Import passes 1 to 3 (their READMEs). Then:

```sh
bootstrap/live-bootstrap-python/import.sh <your actor id>
kairo build object:<wrapper id> --target x86 --actor <your actor id>
```

The build plans the earlier passes' `x86` targets first if their
artifacts aren't held. It takes longer than the default hour: give the
store a larger `[runtime] timeout_secs`. `import.sh` fetches each
distfile as the earlier passes' do, from its upstream URL and then
live-bootstrap's mirrors; the gnulib snapshots and `which` have no
upstream URL, and the mirrors serve them, as they do the snapshots
Savannah's cgit makes on request.

The ignored test `crates/kairo-cli/tests/bootstrap_live.rs` builds this
pass after the first three when `KAIRO_LIVE_BOOTSTRAP_PASSES` is 4 or
more. Pass 5 (`bootstrap/live-bootstrap-gcc-10.5.0/`) goes on from this
pass's root.
