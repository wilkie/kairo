# live-bootstrap pass 3: to gcc 4.7.4 (x86)

The third pass of Kairo's live-bootstrap (`specs/DECISIONS.md` §49): it
goes on from pass 2's whole root (`bootstrap/live-bootstrap-perl/`,
through upstream's perl chain) through the next stretch of upstream's
CI pass 2 for [live-bootstrap](https://github.com/fosslinux/live-bootstrap)
at `b1ceced7`: openssl 3.6.0, ca-certificates 3.119.1, curl 8.17.0 rebuilt
against openssl, and patch 2.8, then **gcc 4.7.4**, the first gcc
live-bootstrap builds with C++, and binutils 2.41 and musl 1.2.5 rebuilt
with it. It runs under the bubblewrap engine, as the earlier passes do,
with no host tool taking part.

Each step packages what it installed and checks the package against
live-bootstrap's `SHA256SUMS.pkgs`. The 7 packages are this pass's 9
children (`specs/DECISIONS.md` §41 sub-decision 6, §51): `tool:gcc`,
`tool:g++`, and `lib:stdc++:static` 4.7.4, which require binutils,
musl's headers, the kernel headers, and `one_of` static or shared musl,
chosen by whatever builds with them, and confer nothing;
`tool:binutils` 2.41; musl 1.2.5, rebuilt, as `lib:musl:headers`,
`lib:musl:static`, and the first `lib:musl:shared`, which confers
itself `^1.2.5` and brings the merged-/usr layout its loader is reached
through (§50); `lib:openssl` and `tool:openssl` 3.6.0;
`data:ca-certificates`; `tool:curl` 8.17.0; and `tool:patch` 2.8. Where
an earlier pass offers the same label at the same version (curl 8.17.0,
musl 1.2.5's headers and static libc), the owner and version tie, and
§48's tie-break decides.

## How it's put together

| Guest path | What | How it's pinned |
|---|---|---|
| `/` | pass 2's whole root: `usr/` and `etc/`, every package so far in `repo/`, and `state/` | artifact, via `data:live-bootstrap:x86:perl-5.42.0` |
| `/steps` | live-bootstrap's `steps/`, at the commit the earlier passes ran; `start.sh` copies this directory's `steps/manifest` over it | source object, by commit |
| `/external/distfiles` | the 22 distfiles this pass's steps unpack | file sources, by SHA-256 |

| File | What it is |
|---|---|
| `kairo.toml` | The pins and placements above; one target, `x86`, run by pass 2's bash with `../live-bootstrap/pass/start.sh`, from the step after `uninstall perl-5.6.2 perl-5.8.9`; its artifact (installed at `/`) is `/usr` and `/etc`, every package so far in `repo/`, the `state/` the next pass needs, and this pass's packages extracted as children. The parent provides the whole root as `data:live-bootstrap:x86:musl-1.2.5_2`, naming the package because musl 1.2.5 is built three times. The children are generated by `../live-bootstrap/children.py`. |
| `steps/manifest` | live-bootstrap's manifest, truncated after musl 1.2.5's third build; its lines up to the perl chain are pass 2's. |
| `import.sh` | Archives live-bootstrap and the distfiles, and creates the wrapper with `../live-bootstrap/pass/start.sh`, `package.sh`, `../live-bootstrap/split-musl.sh`, and `split-gcc.sh`. |

## Running it

Import passes 1 and 2 (their READMEs). Then:

```sh
bootstrap/live-bootstrap-gcc-4.7.4/import.sh <your actor id>
kairo build object:<wrapper id> --target x86 --actor <your actor id>
```

The build plans the earlier passes' `x86` targets first if their
artifacts aren't held. `import.sh` fetches each distfile as pass 2's
does, from its upstream URL and then live-bootstrap's mirrors; the
Unicode data files upstream names on `ftp.unicode.org` are fetched from
`www.unicode.org`, which serves the same bytes over https.

The ignored test `crates/kairo-cli/tests/bootstrap_live.rs` builds this
pass after the first two when `KAIRO_LIVE_BOOTSTRAP_PASSES` is 3, then
builds the hello consumer's dynamic target, which links with gcc 4.7.4
against this pass's shared musl. Pass 4
(`bootstrap/live-bootstrap-python/`) goes on from this pass's root.
