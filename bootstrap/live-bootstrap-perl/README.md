# live-bootstrap pass 2: the perl chain (x86)

The second pass of Kairo's live-bootstrap (`specs/DECISIONS.md` §49):
it goes on from pass 1's whole root (`bootstrap/live-bootstrap/`, which
runs [live-bootstrap](https://github.com/fosslinux/live-bootstrap) at
`b1ceced7` to `zlib-1.3.1` in upstream's CI pass 2) through upstream's
perl chain: `dist` 3.5, then perl 5.8.9, 5.12.5, 5.15.7, 5.16.3,
5.17.2, 5.17.4, 5.18.4, 5.22.4, 5.24.4, 5.30.3, 5.36.3, and 5.42.0,
each built with `Devel::Tokenizer::C` rebuilt for it, with automake
1.16.3, autoconf 2.71, and bison 3.6.4, 3.7.6, and 3.8.2 along the way,
and finally upstream's `uninstall: perl-5.6.2 perl-5.8.9`. It runs
under the bubblewrap engine, as pass 1 does, with no host tool taking
part.

Each step packages what it installed and checks the package against
live-bootstrap's `SHA256SUMS.pkgs`. The 30 packages are this pass's
children (`specs/DECISIONS.md` §41 sub-decision 6): `tool:perl` 5.42.0
and each earlier perl at its version, `tool:autoconf` 2.71,
`tool:automake` 1.16.3, `tool:bison` 3.8.2, `tool:dist`, and
`lib:perl:Devel-Tokenizer-C`. Pass 1's packages stay pass 1's children.

## How it's put together

| Guest path | What | How it's pinned |
|---|---|---|
| `/` | pass 1's whole root: `usr/`, its packages in `repo/`, and `state/` | artifact, via `data:live-bootstrap:x86:zlib-1.3.1` |
| `/steps` | live-bootstrap's `steps/`, at the commit pass 1 ran; `start.sh` copies this directory's `steps/manifest` over it | source object, by commit |
| `/external/distfiles` | the 31 distfiles this pass's steps unpack | file sources, by SHA-256 |

| File | What it is |
|---|---|
| `kairo.toml` | The pins and placements above; one target, `x86`, run by pass 1's bash, whose artifact (installed at `/`) is `/usr`, every package so far in `repo/`, the `state/` the next pass needs, and this pass's 30 packages extracted as children; the parent provides the whole root as `data:live-bootstrap:x86:perl-5.42.0`. The children are generated by `../live-bootstrap/children.py`. |
| `start.sh` | Puts pass 1's root back as its steps left it: links `/external/repo` to `/repo`, copies `state/` into `/steps`, makes `merged_usr`'s links from `/`, and runs upstream's `populate_device_nodes` and `finalize_fhs`. Then runs upstream's `script-generator` over this pass's manifest, and the generated script from the step after `zlib-1.3.1`, and finally `package.sh`. |
| `package.sh` | Copies `/usr`, `/repo`, and the state into `/kairo/package`, and extracts each package this pass made into `/kairo/package/<package>/`. |
| `steps/manifest` | live-bootstrap's manifest, truncated after the perl chain; its lines up to `zlib-1.3.1` are pass 1's. |
| `import.sh` | Archives live-bootstrap and the distfiles, and creates the wrapper. |

## Running it

Import pass 1 (`bootstrap/live-bootstrap/README.md`). Then:

```sh
bootstrap/live-bootstrap-perl/import.sh <your actor id>
kairo build object:<wrapper id> --target x86 --actor <your actor id>
```

The build plans pass 1's `x86` target first if its artifact isn't held.
`import.sh` fetches each distfile from its upstream URL, then from
live-bootstrap's mirrors: its maintainers' two, then archive.org. The
gnulib snapshots have no upstream URL; upstream's `mirror.sh` makes
them, and GitHub's archive tarballs, with `git archive`, and the
mirrors serve those bytes. The SHA-256 pins them whichever serves them.

The ignored test `crates/kairo-cli/tests/bootstrap_live.rs` builds this
pass after pass 1 when `KAIRO_LIVE_BOOTSTRAP_PERL` is set.
