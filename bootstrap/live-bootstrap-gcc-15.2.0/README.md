# live-bootstrap pass 6: gcc 15.2.0 and the end (x86)

The sixth and last pass of Kairo's live-bootstrap (`specs/DECISIONS.md`
§49): it goes on from pass 5's whole root
(`bootstrap/live-bootstrap-gcc-10.5.0/`, to gcc 10.5.0) through the rest
of upstream's CI pass 2 for
[live-bootstrap](https://github.com/fosslinux/live-bootstrap) at
`b1ceced7`: **gcc 15.2.0**, bootstrapped in three stages with C and C++,
then libmd 1.1.0, libbsd 0.11.8, shadow 4.14.3, opendoas 6.8.2, gzip
1.13, diffutils 3.10, gawk 5.3.0, m4 1.4.19, and libarchive 3.5.2, and
upstream's closing steps. grub isn't built: its predicate,
`BUILD_LINUX`, is false for a chroot, as it is for upstream's own. It
runs under the bubblewrap engine, as the earlier passes do, with no
host tool taking part; gcc 15's bootstrap at upstream's two jobs takes
it about three hours.

Each step packages what it installed and checks the package against
live-bootstrap's `SHA256SUMS.pkgs`; with this pass, all 149 packages of
upstream's CI pass 2 are built and checked. The 10 packages are this
pass's children (`specs/DECISIONS.md` §41 sub-decision 6, §51): gcc
15.2.0, providing `tool:gcc`, `tool:g++`, `lib:stdc++:static`, and
`lib:stdc++:shared` and `lib:gcc:shared` (`libstdc++.so.6`,
`libgcc_s.so.1`), each conferring itself `>=15.2.0`, requiring
binutils, musl's headers, the kernel headers, and `one_of` static or
shared musl; `lib:md`; `lib:bsd`; `tool:shadow`; `tool:opendoas` and
`tool:doas`; `tool:gzip` 1.13; `tool:diffutils` and `tool:diff` 3.10;
`tool:gawk` and `tool:awk`; `tool:m4` 1.4.19; and `lib:archive` and
`tool:bsdtar`.

## How it's put together

| Guest path | What | How it's pinned |
|---|---|---|
| `/` | pass 5's whole root: `usr/` and `etc/`, every package so far in `repo/`, and `state/` | artifact, via `data:live-bootstrap:x86:binutils-2.41_1` |
| `/steps` | live-bootstrap's `steps/`, at the commit the earlier passes ran; `start.sh` copies this directory's `steps/manifest` over it | source object, by commit |
| `/external/distfiles` | the 14 distfiles this pass's steps unpack | file sources, by SHA-256 |

| File | What it is |
|---|---|
| `kairo.toml` | The pins and placements above; one target, `x86`, run by pass 5's bash with `../live-bootstrap/pass/start.sh`, from the step after `build binutils-2.41 pass2.sh`; its artifact (installed at `/`) is `/usr` and `/etc`, every package in `repo/`, the `state/`, and this pass's packages extracted as children. The parent provides the whole, finished root as `data:live-bootstrap:x86:libarchive-3.5.2`. The children are generated by `../live-bootstrap/children.py`. |
| `steps/manifest` | live-bootstrap's manifest, whole; only its header comment is Kairo's. |
| `import.sh` | Archives live-bootstrap and the distfiles, and creates the wrapper with `../live-bootstrap/pass/start.sh`, `package.sh`, and `../live-bootstrap/split-musl.sh`. |

## Running it

Import passes 1 to 5 (their READMEs). Then:

```sh
bootstrap/live-bootstrap-gcc-15.2.0/import.sh <your actor id>
kairo build object:<wrapper id> --target x86 --actor <your actor id>
```

The build plans the earlier passes' `x86` targets first if their
artifacts aren't held. It takes hours: give the store a `[runtime]
timeout_secs` of 28800 or more.

The ignored test `crates/kairo-cli/tests/bootstrap_live.rs` builds this
pass after the first five when `KAIRO_LIVE_BOOTSTRAP_PASSES` is 6, then
builds the hello consumer's dynamic target again, which now compiles
with gcc 15.2.0.
